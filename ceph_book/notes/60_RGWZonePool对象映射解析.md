# RGW Zone/Pool/对象映射关系解析

## 1. 核心概念定义
在 RGW 架构中，Zone、Pool、Bucket 和 Object 构成了一个**从逻辑策略到物理存储**的完整层级：

| 概念 | 定义 | 作用域 | 类比 |
| :--- | :--- | :--- | :--- |
| **Zone** | **配置与规则的集合** | 全局/区域 | "交通指挥中心"：规定什么类型的车（数据）走什么车道（Pool）。 |
| **Pool** | **RADOS 存储池** | 集群物理层 | "专用停车场"：实际存放车辆（数据块）的场地，不同池通常对应不同性能硬件。 |
| **Bucket** | **逻辑容器与路由枢纽** | 用户层 | "车队"：拥有自己的属性，通过绑定“调度策略”，决定车队停哪个停车场。 |
| **Object** | **具体存储的数据实体** | 集群逻辑层 | "车辆/货物"：最终落盘的实体。 |

## 2. Bucket 的核心地位
Bucket（存储桶）不仅仅是存放文件的逻辑文件夹，它在底层映射中起到了**关键的路由枢纽**作用：
*   **物理本质**：Bucket 自身是一个存在 `domain_root` 池中的 RADOS 对象（存储 `RGWBucketInfo`）。
*   **路由功能**：Bucket 内部有一个关键属性 `placement_rule`（存储策略）。RGW 根据这个字符串，去 Zone 中查找映射表，从而决定**数据**去哪个池，**索引**去哪个池。

## 3. 数据流向与映射详解

根据书中 `7.2.4` 和 `RGWZoneParams` 源码定义，数据被分为两类，映射路径不同：

### A. 系统/控制数据（硬编码映射）
RGW 的系统元数据直接根据 **Zone 定义** 写入固定的专用池：

*   **用户信息 (User Info)** `user_id` -> 写入 Zone 指定的 `user_keys_pool`。
*   **存储桶元数据 (Bucket Info)** -> 写入 Zone 指定的 `domain_root`。
*   **后台任务数据** (如 GC) -> 写入 Zone 指定的 `gc_pool`。

### B. 用户上传数据（动态路由映射）
用户上传的文件（Data）和文件列表（Index）通过 **Bucket 的策略** 动态路由：

1.  **查找策略**：用户向 Bucket 写入数据。
2.  **策略解析**：RGW 读取 Bucket 的 `placement_rule`。
3.  **匹配 Zone 映射表**：在 Zone 的 `placement_pools` 列表中找到对应名称的条目。
4.  **数据分流**：
    *   **实际文件内容 (Data Objects)** -> 分配给该条目的 `data_pool`。
    *   **Bucket 索引对象 (Index Objects)** -> 分配给该条目的 `index_pool`。

## 4. 总结
> **Zone 是规则，Pool 是位置，Bucket 是指路人，Object 是落脚点。**
>
> 当 RGW 处理一个请求时，它会根据数据类型（元数据还是文件），查阅 Zone 定义的规则表（通过 Bucket 的策略），最终将数据写入正确的 RADOS 对象所在的 Pool 中。
