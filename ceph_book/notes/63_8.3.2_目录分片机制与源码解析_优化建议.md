# Note 63 优化建议

## 1. 目录分片的自动触发阈值
- **原文问题**：原文提到目录分裂阈值（如 1 万）。
- **优化建议**：补充说明现代 Ceph MDS 使用 **`mds_bal_split_size`** 和 **`mds_bal_split_rd`/`mds_bal_split_wr`** 等参数动态控制分裂。MDS 不仅根据目录项数量，还根据访问频率（Load）来决定是否分裂。这避免了在冷数据大目录上无谓的分裂开销。

## 2. `EExport` 日志的现代演进
- **原文问题**：原文提到 `EExport` 日志记录迁移状态。
- **优化建议**：在现代 Ceph 版本中，MDS 日志系统已被整合到 **`mds_journal`** 中，并支持更细粒度的事务记录。`EExport` 依然是核心事件，但迁移过程现在支持 **增量迁移**（只迁移变化的 Dentry），而不再是全量打包。这极大减少了大目录迁移时的网络带宽占用和停顿时间。

## 3. `Bounds` 机制的精确实现
- **原文问题**：原文提到 Bounds 记录切分出的本地子树。
- **优化建议**：明确指出 `Bounds` 实际上是一个 **`set<frag_t>`** 集合。当 MDS 持有某个目录的副本时，它会检查请求的路径 Hash 是否落在 `Bounds` 中的任何一个 Fragment 范围内。如果是，则直接在本地处理；否则，转发给权威 MDS。这种基于 Hash 范围的匹配确保了路由的精确性。

## 4. 源码位置
- **优化建议**：目录分片逻辑位于 `src/mds/CDir.cc` 的 `split_if_necessary` 函数。子树迁移逻辑位于 `src/mds/Migrator.cc` 的 `export_dir` 和 `import_dir` 函数。`replica_map` 的管理位于 `src/mds/CDir.h` 和 `MDCache::replica_map`。
