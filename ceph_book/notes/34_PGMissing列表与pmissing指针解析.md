# 34. PG Missing 列表与 pmissing 指针解析

本节详细解析 OSD 在执行读写请求时，如何利用 `pmissing` 机制来判断对象的可读性与一致性。

## 1. 什么是 PG Missing 列表？

在 Ceph 的分布式恢复（Recovery）与回补（Backfill）机制中，集群的状态可能处于不一致的中间态。为了追踪哪些对象尚未同步到最新状态，PG（Placement Group）在内存中维护了一个 **`missing` 列表**。

针对列表中的每一个正在恢复或缺失的对象，都会生成一个 **`pg_missing_item`** 类型的结构体。该结构体记录了对象恢复所需的关键元数据：

*   **`have`**：该对象目前在本 OSD 上持有的版本（Version）和位置。如果是完全丢失或空对象，可能为 0。
*   **`need`**：该对象在集群中应该达到的最新版本（Version）。
*   这些信息决定了当前 PG 是否能够对外提供读写服务，或者需要从哪里拉取数据。

## 2. 什么是 `pmissing`？

`pmissing` 是一个 C++ 指针变量（Pointer to `pg_missing_item`），它指向 `missing` 列表中特定对象对应的条目。

在图 4-3 (`do_op` 对象级检查) 中，当提到“设置 pmissing 为 head 对象”时，其源码逻辑实质上是进行一次 **查找操作**：

*   **动作**：PG 使用请求中的 `hobject_t`（对象的完整身份标识）作为 Key，在内存中的 `missing` 列表中进行哈希查找。
*   **结果赋值**：
    *   **若找到**：`pmissing` 指向该对象的 `pg_missing_item` 条目。这意味着该对象当前正处于恢复中、降级中或丢失状态。
    *   **若未找到**：`pmissing` 为空（通常为 `null` 或特定的结束迭代器）。这意味着该对象在当前 OSD 是完整且最新的。

## 3. 为什么要在执行 Op 时检查 `pmissing`？

在 Worker 线程从 `op_shardedwq` 提取 Op 并准备执行具体的数据读写前，必须确认**“我要读/写的这个对象现在能不能动？”**。

### 3.1. 写入保护
如果 `pmissing` 不为空（即对象在 Missing 列表中），且该 Op 包含写操作，必须非常小心。
*   如果直接写入，可能会与后台正在进行的 Recovery 流程（如从其他 OSD 拉取旧版本数据）发生冲突，导致 **陈旧写入（Stale Write）** 或数据覆盖。

### 3.2. 读取降级
对于读操作，如果 `pmissing` 不为空且本地没有有效数据（`have` 版本不满足要求），则当前节点无法提供读取服务。

### 3.3. 调度决策
检查 `pmissing` 的结果直接决定了 Op 的下一步调度：
1.  **`pmissing` 为空**：对象健康。Op 继续向下流转，执行 `executectx`（真正的读写逻辑）。
2.  **`pmissing` 不为空**：对象异常。Op 将被拦截并放入 PG 的内部等待队列：
    *   若对象彻底丢失/无法读取：进入 `waiting_for_unreadable_object`。
    *   若对象处于降级状态（本节点无数据，但可以从 Replica 恢复）：进入 `waiting_for_degraded_object`。

## 4. 总结
`pmissing` 是 Ceph 保证**读写操作与后台恢复操作隔离**的关键探针。通过查询该指针是否为空，OSD 能够精准识别出那些“正在修补中”的对象，从而避免破坏数据一致性或返回错误数据。
