# 40. PG 内部状态机与外部状态的源码映射

本节从源码层面解析图 4-9（内部状态机状态）与表 4-15（外部状态）的区别与联系。

## 1. 本质区别

*   **图 4-9 的内部状态（State Machine States）**：
    *   **源码本质**：它们是继承自 `boost::statechart::state` 的 **C++ 类 (Class)**。
    *   **作用**：它们定义了 **行为 (Behavior)**。每个状态都有 `entry()`（进入时做什么）和 `exit()`（离开时做什么）函数，以及处理事件的 `react()` 函数。
    *   **位置**：`src/osd/PG.h` 和 `src/osd/PG.cc`。

*   **表 4-15 的外部状态（External States）**：
    *   **源码本质**：它们是定义在 `enum pg_state_t` 中的 **枚举值 (Enum)**，实际表现为 **位掩码 (Bitmask)**。
    *   **作用**：它们定义了 **标签 (Labels)**。用于向 Monitor 汇报 PG 当前的健康状况和功能状态。
    *   **位置**：`src/osd/osd_types.h` (如 `PG_STATE_ACTIVE`, `PG_STATE_PEERING`)。

---

## 2. 源码映射：内部如何驱动外部？

外部状态并不是独立存在的，而是由内部状态机在流转过程中**动态点亮或熄灭**的。

**映射机制：**
当内部状态机进入某个状态（例如 `Peering`）时，它会调用 `state_set()` 设置对应的位掩码；离开时调用 `state_clear()` 清除掩码。

**源码示例：**

```cpp
// src/osd/PG.h
// 内部状态机：Peering 状态的定义
struct Peering : boost::statechart::state< Peering, Started > {
    // ...
    void entry() override {
        // 【关键映射点】
        // 当内部状态机进入 Peering 状态时，点亮外部状态的 PG_STATE_PEERING 灯
        pg->state_set(PG_STATE_PEERING); 
        
        // 执行实际的 Peering 逻辑...
    }

    void exit() override {
        // 【关键映射点】
        // 当内部状态机离开 Peering 状态时，熄灭这盏灯
        pg->state_clear(PG_STATE_PEERING);
    }
};
```

## 3. 为什么外部状态可以“叠加”？

因为外部状态是 **Bitmask（位图）**，而内部状态是 **互斥的 Class**（同一时刻只能处于一个内部状态）。

**源码示例：Active + Degraded**
当内部状态机处于 `Started/Active` 状态时，`PG_STATE_ACTIVE` 灯是亮着的。
此时，如果代码逻辑（在 `Active` 状态的 `react()` 或定时检查中）发现数据副本数不足：

```cpp
// src/osd/PG.cc (在 Active 状态下执行)
void PG::check_degraded() {
    if (actingset.size() < pool.info.size) {
        // 手动点亮 Degraded 灯，但不改变内部状态机状态
        state_set(PG_STATE_DEGRADED); 
    }
}
```

**结果**：
*   **内部状态**：依然是 `Started/Active`（代码还在 Active 类的逻辑里跑）。
*   **外部状态**：变成了 `PG_STATE_ACTIVE | PG_STATE_DEGRADED`（用户看到 `active+degraded`）。

## 4. 总结

| 特性 | 内部状态机 (图 4-9) | 外部状态 (表 4-15) |
| :--- | :--- | :--- |
| **源码形式** | `struct Peering : state<...>` | `#define PG_STATE_PEERING 0x00000002` |
| **关注点** | **过程 (Process)**：下一步该发什么消息？ | **结果 (Result)**：现在能不能读写？ |
| **生命周期** | 互斥：同一时刻只能在一个状态 | 叠加：多个标志位可以同时为 1 |
| **驱动关系** | **驱动者**：通过 `entry/exit` 设置外部状态 | **被驱动者**：反映内部状态机的运行阶段 |

**一句话总结**：
图 4-9 是引擎盖下的**齿轮**（代码执行流），表 4-15 是仪表盘上的**指示灯**（运行结果）。齿轮转动（内部状态流转），带动指示灯亮起或熄灭（外部状态变化）。
