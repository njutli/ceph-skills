# Note 12 优化建议

## 1. 客户端库明确化
- **原文问题**：原文泛指"客户端"。
- **优化建议**：明确指出 Ceph 的原生客户端库是 **`librados`**（以及基于它的 `librbd`、`libcephfs`）。这些库内置了 CRUSH 算法和 OSDMap 缓存逻辑。对于通过 RGW 或 NFS 网关访问的用户，网关充当了客户端角色，底层同样遵循此机制。

## 2. OSD 拦截的具体行为
- **原文问题**：原文提到"OSD 会拒绝处理该请求，并返回特定错误码"。
- **优化建议**：补充说明 OSD 的具体行为通常是返回 **`EAGAIN`** 错误码或 **`Redirect`** 消息，提示客户端"你的 Map 版本过旧，请更新后重试"。客户端收到后，会立即向 Monitor 发起 `get_osdmap` 请求拉取最新增量。

## 3. 增量更新的限制
- **原文问题**：原文提到 Monitor 发送"变更包（增量数据）"。
- **优化建议**：补充说明如果客户端落后版本过多（超过 `mon_max_osdmap_epochs` 或类似阈值），Monitor 可能会直接下发**全量 OSDMap**，因为累积的增量可能比全量还大，或者中间版本已过期被清理。

## 4. 源码位置补充
- **优化建议**：客户端计算逻辑位于 `src/osdc/Objecter.cc`（`librados` 的核心调度器）。OSD 端检查逻辑位于 `src/osd/PG.cc` 的 `check_map_epoch` 相关函数。
